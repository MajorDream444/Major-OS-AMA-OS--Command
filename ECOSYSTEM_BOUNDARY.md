# AMA Command Center Ecosystem Boundary

Status: Stage A foundation
Owner: Major Dream Williams

This document defines what the AMA Command Center owns and what it must not absorb.

## Canonical Boundary

```txt
AMA Command Center coordinates.
MAIM teaches.
HAMAL provides doctrine and orchestration standards.
Major-AI-OS holds reusable product/system layer.
52in52 builds weekly apps.
Hanzo provides AI infrastructure.
Lux provides sovereignty.
Airtable tracks operations.
Notion presents the human dashboard.
```

## What AMA Command Center Owns

- operator entrypoints
- dashboard shell
- app registry views
- workflow registry views
- agent status visibility
- Airtable / Notion / GitHub coordination surfaces
- Codex and OpenClaw handoff files
- admin workflows
- sync status visibility
- local/mock mission control until live execution is approved

## What AMA Command Center Does Not Own

- MAIM education, community, ABC, or Command Room content
- HAMAL doctrine, SOPs, rubrics, or playbook ownership
- reusable product/system logic that belongs in `Major-AI-OS`
- individual app implementations that belong in `52in52`
- operational records that belong in Airtable
- human planning dashboards that belong in Notion
- Hanzo source code
- Lux sovereignty implementation
- live external writes without approval

## Current Stage

AMA Command Center is in Stage A - Foundation.

This means:

- docs and entrypoints first
- local/mock command center only
- no live integrations
- no external writes
- no autonomous execution

## Language Rules

Use:

```txt
AMA Command Center coordinates.
HAMAL provides doctrine and orchestration standards.
Hanzo provides AI infrastructure.
```

Avoid:

```txt
AMA Command Center owns all doctrine.
Hanzo gives ecosystem intelligence.
Command Center absorbs every system.
```
